# Mic Noize

Windows 11 x64: **Rust / Iced 0.14 UI + C++20 аудиодвижок**. Личная локальная сборка: NVIDIA-шумоподавление микрофона, локальные голосовые модификаторы, опциональный RVC, постоянный виртуальный микрофон для Discord и игр.

**QuadCast S → NVIDIA Denoiser → RVC (опционально) → модификаторы → boost → TAG → Discord / игры.**

История изменений и результаты всех проверок — в [CHANGELOG.md](CHANGELOG.md). Для нового чата Codex/Claude открывайте эту папку: правила — в [AGENTS.md](AGENTS.md), карта кода и рабочий процесс — в [скилле micnoize](.agents/skills/micnoize/SKILL.md).

## Компоненты

- NVIDIA Audio Effects SDK **3.0.0.51**, Denoiser **3.0.0.0**, 48 кГц v1/v2. Модели TensorRT собраны под архитектуру GPU: движок определяет видеокарту через `nvcuda.dll` (compute capability устройства CUDA 0) и берёт `models/turing|ampere|ada|blackwell`; core содержит только Ampere, модели другой архитектуры UI докачивает отдельным подписанным компонентом `runtime-models-v3.0.0/models-<arch>.json` вместе с core (автостарт ждёт). Если NVIDIA недоступна (не RTX, AMD/Intel, нет модели, `NvAFX_Load` не прошёл), движок включает **DeepFilterNet 3 на процессоре** (MIT/Apache-2.0, модель встроена в `MicNoize.exe`, `ui/src/cpu_denoise.rs`): кадры 480 сэмплов 48 кГц, **+30 мс** задержки (замер корреляцией: 1440 сэмплов), около 0,2–0,3 мс на 10-мс блок на Ryzen 7 7800X3D. Регуляторы шумоподавления работают как предел ослабления: 100–200 % — полное, ниже — 40 дБ × сила, минимум 0,5 дБ (ровно 0 дБ модель пропускает без задержки, и хоткей «при удержании» сдвигал бы звук). Под регуляторами показано «Шумодав DeepFilterNet на процессоре» и причина, почему не NVIDIA. Если и DFN не создаётся (например, в нативных проверках без Rust), голос идёт **без шумодава**, а причина показана оранжевым. Голос, RVC, эффекты, саундпад, TAG/WASAPI и Mute работают во всех режимах. Состояние: C ABI `mnr_denoiser_state` (1 NVIDIA, 2 без шумодава, 3 CPU), `denoiser=nvidia|bypass|cpu` в `sessions.log`, строка в `app.log`. `MNR_DENOISER=cpu` принудительно включает CPU и на RTX (проверки, свободная видеокарта в играх). Приложение регистрирует DFN в движке через `mnr_set_cpu_denoiser`, поэтому нативные проверки собираются без Rust. Цена: `MicNoize.exe` вырос с ~11 до ~34 МБ (tract + модель 8 МБ). Наушники с галкой «Шумодав NVIDIA» по-прежнему требуют NVIDIA. Программа не запускает Broadcast; runtime и модели NVIDIA не изменены, SHA-256 в `nvidia-assets.sha256`. v2 экспериментальная: равенство или превосходство качества над Broadcast не заявляется. Speaker Focus исключён.
- Thin Audio Gateway (TAG) 2.0.0.1903 demo — подписанный Microsoft виртуальный аудиодрайвер; `mic_tag_host.exe` держит его открытым постоянно.
- Rubber Band 4.0.0 LiveShifter — pitch без изменения темпа.
- VCClient 2.1.4-alpha (w-okada/voice-changer) — RVC-сервер как отдельный процесс, REST на `127.0.0.1:18889`.
- VB-CABLE текущим приложением не используется (удалён 2026-09-18); Voicemeeter поддерживается как альтернативный виртуальный выход.

| Исходник | Назначение |
|---|---|
| `ui/src/main.rs`, `view.rs` | Rust UI, состояния, фокус и управление |
| `ui/src/engine.rs`, `settings.rs`, `rvc.rs` | C ABI, управляющий поток, совместимый INI, модели RVC |
| `src/audio.cpp`, `audio.hpp` | NVIDIA / WASAPI / TAG, очереди, RVC-клиент, телеметрия |
| `src/tag_host.cpp`, `tag_link.hpp`, `tag.hpp` | Постоянный TAG-хост, передача отсчётов, официальный API драйвера |
| `src/effects.hpp`, `hotkeys.hpp` | Pitch, boost, фразы, реверс, повтор, сглаживание и удержание |
| `src/bridge.cpp`, `bridge.h` | C API, трей, опрос клавиш, системные события |
| `src/vcclient_server.py`, `rvc_import.py` | RVC-сайдкар и импорт моделей |
| `src/*check.cpp`, `src/rvc_*check.py` | Самопроверки и реальные аудиопрогоны |

UI использует Iced daemon и tiny-skia; wgpu / WebView не включены. NVIDIA работает в DSP-потоке; управление устройствами и жизненным циклом — в управляющем потоке Rust; горячие регуляторы передаются атомарно. Старый Win32-интерфейс удалён.

## Установка и обновления

Публичные версии **Mic Noize** выходят в репозитории `Arkanoidvfx/MicNoize` как `Setup.exe`. Установщик и фоновые обновления сделаны через Velopack: новая версия скачивается в фоне, после чего под вкладками на любой странице появляется панель «Доступно обновление» с кнопкой «Обновить и перезапустить» (та же кнопка осталась и в настройках). Программа закрывается, обновление применяется и она запускается снова. Перед этим кнопка ещё раз проверяет GitHub и, если за время работы в трее вышла версия новее скачанной, докачивает и ставит сразу её (без сети ставится уже скачанная), так что одно нажатие всегда ведёт на последнюю версию. Платная Authenticode-подпись пока не используется, поэтому Windows SmartScreen может показать предупреждение издателя.

Основной NVIDIA/TAG runtime устанавливается отдельно при первом запуске. Сразу после него программа проверяет, установлен ли на этом ПК подписанный TAG-драйвер, и при его отсутствии ставит сам: один запрос UAC, `wdmdrvmgr.exe` с тем же INF, что и `install-tag.ps1`, настройки безопасности Windows не меняются. Если запрос отклонён, виртуальный микрофон не появится: в настройках остаётся кнопка «Установить виртуальный микрофон», она повторяет запрос без перезапуска программы. Пока идёт установка runtime или драйвера, автозапуск обработки ждёт. RVC runtime загружается только при первом включении Voice Changer. Модели голоса пользователя (`.pth`, `.index`, `.onnx`, `params.json`) не входят в релизы и должны импортироваться отдельно. Манифесты компонентов подписаны Ed25519, каждый архив и его части проверяются по SHA-256; уже скачанная валидная часть повторно используется после ошибки. Настройки, install ID, runtime и модели хранятся в `%APPDATA%\Mic Noize`, отдельно от программы в `%LOCALAPPDATA%\MicNoize`, и должны переживать её удаление. При первом запуске 0.2.0 `settings.ini` копируется из прежней `%LOCALAPPDATA%\MicNoiseReducer` (legacy migration); старые Components не переносятся.

Сборка релиза: `scripts\package-release.ps1 -Version 0.2.0 -Stage`; отдельные компоненты: `scripts\package-components.ps1`. Workflow `release.yml` на GitHub-hosted Windows скачивает опубликованный core runtime, проверяет проект и выпускает приложение. Редкие runtime-релизы собираются локально из vendor-папок, подписываются `COMPONENT_SIGNING_KEY` и публикуются через `gh release create`; эти большие сторонние входы намеренно не лежат в Git. Секрет приложения: `MNR_TELEMETRY_SECRET`; без него (локальные сборки) телеметрия и отправка отчётов выключены. Кнопка «Отправить разработчику» на вкладке «Логи» шлёт заметку о состоянии UI и хвосты `results/app.log`, `nvafx.log`, `tag-host.log`, `sessions.log`, `tag-headphones.log` (по 2 КБ) как события `error` в панель оператора Mic Noize — отдельный воркер `micnoize-telemetry` со своей базой D1 (конфиг `telemetry/worker/wrangler.micnoize.toml` в репозитории Moment Player, код воркера общий); записи помечены `app_id = mic_noize`. Голос, имена файлов пользователя и содержимое моделей не отправляются.

Версия 0.2.0 завершает внутренний rename в **Mic Noize**: пакет/EXE, репозиторий, Win32-объекты и TAG-линии получили новые имена. Цепочка обновления 0.1.x намеренно не продолжается. `MNR` означает **Mic Noize Runtime**; ABI `mnr_*`, переменные `MNR_*`, `/mnr/` и `mnr_vcclient_server.exe` остаются без изменений.

## Сборка и запуск

Требуются Visual Studio 2022 C++ Build Tools, Windows SDK, CMake и Rust **1.97+ x86_64-pc-windows-msvc**. Проверено на Rust 1.97.1, MSVC 19.44 / SDK 10.0.26100.0. Отдельные CUDA Toolkit, TensorRT, Python и Node.js для запуска не нужны. Официальные NVIDIA, TAG и VCClient 2.1.4-alpha уже находятся в `vendor` (не в Git); права и условия их использования остаются отдельными.

```powershell
Set-Location D:\Projects\Audio\MicNoize
.\build.ps1
.\verify.ps1
.\enable-tag-host.ps1
.\run.ps1
```

`build.ps1` скачивает закреплённый Rubber Band 4.0.0 с проверкой SHA-256, собирает C++ и Rust по Cargo.lock. Кеш Cargo — `.cache/cargo`, результаты — `build`, exe — `bin`. `-NativeOnly` собирает только C++; `-Samples` — официальные примеры NVIDIA. Полный `build.ps1` пересобирает и `mic_tag_host`, и копирует UI поверх установленного — при работающих процессах он упадёт; для инкрементальной сборки см. [workflow.md](.agents/skills/micnoize/references/workflow.md).

`verify.ps1` пересобирает `mic_engine` и проверочные exe (`mic_check`, `effects_check`, `bridge_check`; хост и UI не трогает), затем запускает CTest, Rust-тесты и строгий Clippy. NVIDIA для этого не нужен.

Готовая dev-сборка: `bin\MicNoize.exe` (`Run.bat` = `run.ps1` с проверкой VRAM; запускать из Проводника, не из терминала агента). Она читает и сохраняет `%APPDATA%\Mic Noize\settings.ini`, но при наличии `vendor\nvidia-afx-3.0.0` всегда использует runtime и модели из репозитория; установленная версия использует `%APPDATA%\Mic Noize\Components`. При открытии программа сама выбирает сохранённые устройства и запускает обработку; без сохранённого выбора берётся HyperX, иначе микрофон связи по умолчанию Windows; допустимый виртуальный выход — TAG или Voicemeeter. В Discord или игре выберите **Mic Noize (Thin Audio Gateway)**. Суффикс — имя подписанного TAG-драйвера; наша capture-линия называется `MicNoize Microphone`. Установка TAG на новом ПК выполняется самой программой при первом запуске; `.\install-tag.ps1` остаётся путём разработчика (дополнительно проверяет подписи через signtool из Windows SDK).

## Постоянный виртуальный микрофон

`mic_tag_host.exe` постоянно владеет TAG; UI и шумодав передают ему готовые отсчёты через подтверждаемый блок разделяемой памяти. Второй очереди воспроизведения нет. При выключенном движке хост выдаёт точную тишину, не открывает физический микрофон и не загружает NVIDIA. Если производитель звука прекращает передачу дольше чем на 50 мс, хост переходит на тишину; когда производитель возвращается, он заново регистрируется и продолжает в той же сессии (одна короткая пауза, счётчик `reconnects` в `sessions.log`). Если нет принимающего клиента, аудиотаймер хоста отключён. Если обработка всё же остановилась с ошибкой (хост пропал, микрофон отвалился после сна, устройство не готово при старте), UI сам перезапускает её через 2, 5, 15, 30 и 60 с, показывая обратный отсчёт; новый хост поднимается при перезапуске. После пяти неудач ошибка остаётся на экране до «Обновить устройства»; минута нормальной работы обнуляет счётчик попыток. [Официальное описание TAG](https://software.muzychenko.net/en/thin-audio-gateway/).

Пока обработка через TAG запущена, Mic Noize удерживает системный уровень **своего** виртуального микрофона на 100 % и снимает его системный Mute. Перед TAG программа ослабляет готовый PCM на величину максимального усиления этого endpoint в дБ (на проверенном ПК +30 дБ), поэтому при 100 % итоговый уровень для **обычного общего режима захвата Windows** остаётся нейтральным. Контроль уровня проверяется каждые 50 мс; если другая программа сдвинет ползунок вниз, возможна короткая просадка до восстановления, но не скачок громкости вверх. Громкость физического микрофона и собственный Mute Mic Noize не меняются; после остановки обработки системный уровень не удерживается. В эксклюзивном режиме Windows обходит программную регулировку endpoint: с этой компенсацией такой клиент получит более тихий звук. Этот режим ещё не поддержан. Подписанный драйвер и постоянный TAG host не заменяются.

Тоггл **«Держать виртуальный микрофон доступным после входа в Windows»** в настройках управляет автозапуском хоста текущего пользователя (HKCU Run); администратор не нужен. То же скриптом: `enable-tag-host.ps1` включает автозапуск и запускает хост сейчас, `enable-tag-host.ps1 -Disable` удаляет только автозапуск. UI тоже запускает отсутствующий хост. **Выход** закрывает UI и шумодав, но оставляет этот небольшой процесс: без него TAG по своему устройству переходит в «не подключено».

Start/Stop не удаляет и не пересоздаёт виртуальную линию, идентификатор устройства сохраняется. Это не системная служба до входа в Windows: завершение самого хоста, выход из Windows или сбой драйвера всё ещё отключат endpoint. Запуск игр до выполнения автозапуска хоста после входа тоже не даёт гарантии; запускайте их после появления устройства. Тот же хост обслуживает линию наушников (`HeadphoneLink.v1`, отдельно от `TagLink.v1`); TAG допускает одного владельца драйвера.

Штатный запрос периода — 5 мс; реальный QuadCast S использует 10 мс. Буфер 40 мс — запас от обрывов, не полная задержка. Речевой замер через TAG дал около 120 мс без Discord (см. CHANGELOG).

## Интерфейс

Вкладки слева: «Микрофон», «Наушники», «Voice Changer», «Саундпад»; «Логи» и «Настройки» — справа. Tab следует этому порядку; Tab / Shift+Tab перемещают видимый фокус, Enter / Space активируют, стрелки меняют громкость, эффекты и параметры; Esc возвращает из RVC/саундпада/настроек к эффектам. Шапка, вкладки и сообщения об ошибках закреплены над прокручиваемой областью; прокрутка — страховка для длинных ошибок и маленьких экранов. Минимальный размер окна 820×820 логических пикселей; 620×440 доступен только QA-флагом `--ui-small`. Неизвестные клавиши обозначены кодом `VK 0x…`.

Главный экран: строка маршрута (микрофон выбирается кликом по названию; во время обработки выбор перезапускает тракт), индикатор выходного уровня, два регулятора шумоподавления, таблица пяти эффектов с колонками хоткеев микрофона/Discord, внизу два столбца: слева прослушивание и две галочки монитора, справа повтор последнего, громкость Discord и шесть последних записей. Статус фразы и кнопка отмены появляются во время записи/воспроизведения; ошибки Discord показываются только при активной операции, подключении или ошибке.

Фоновый UI: при потере фокуса, сворачивании или скрытии в трей опрос индикатора и его затухание отключены; служебный цикл — раз в 250 мс вместо 50 мс. Аудио, native-опрос хоткеев и heartbeat продолжают работать независимо.

**Крестик** сворачивает окно в трей, обработка продолжается. Клик по значку программы в панели задач, когда окно активно, тоже убирает его в трей (как в OBS); кнопка «−» сворачивает в панель задач как обычно. Любое другое системное сворачивание (например, Win+M) тоже уводит окно в трей. Меню значка: **Открыть Mic Noize**, **Перезапустить**, **Выход**. Перезапуск сохраняет настройки и останавливает UI/движок перед запуском нового процесса, не завершая `mic_tag_host`. Повторный запуск показывает существующее окно. Оранжевый микрофон встроен в EXE; при ошибке создания значка трея окно остаётся открытым.

Выход микрофона, модель (Denoiser v1 / v2) и буфер (10–80 мс) меняются при остановленной обработке в настройках. Отсутствующее сохранённое устройство не заменяется другим автоматически: подключите его, нажмите «Обновить устройства» — обработка запустится снова. Ошибка тракта останавливает обработку и показывается вверху окна; повторный запуск — тем же «Обновить устройства» или сменой микрофона.

## Шумоподавление

- Основной уровень 0–200 %; 101–200 % помечены как эксперимент и напрямую передаются SDK без второго прохода. Официальный диапазон NVIDIA — 0–100 %; SDK может отклонить запрос или ограничить воздействие. При отказе возвращается явная ошибка с указанием вернуть 100 %. Увеличение силы подавления не подтверждено. 0 % не является обходом вызовов SDK.
- **«При удержании»** — второй уровень (по умолчанию 15 %) с отдельным хоткеем (по умолчанию не назначен). Пока клавиша удерживается, DSP применяет второй уровень к NVIDIA, после отпускания — основной, без перезапуска модели. Значения сохраняются в `[audio] intensity` / `alternate_intensity`, хоткей — `[effects] noise_key`. Работает вне фокуса и в трее; Mute, остановка, потеря клиента, lock/sleep, переназначение и heartbeat старше 250 мс возвращают основной уровень и требуют свежего нажатия. Discord обходит NVIDIA, настройки наушников независимы.
- Входную громкость задаёт Windows у физического микрофона; основной уровень выхода фиксирован на 100 %.

## Эффекты и хоткеи

Десять назначений: пять эффектов × два источника («Микрофон» и «Discord»), плюс прослушивание, повтор последнего и второй уровень шумоподавления. Под каждым эффектом нажмите **Назначить**, отпустите исходные кнопки, нажмите клавишу/сочетание или Mouse 3/4/5 и подтвердите. Ctrl/Alt/Shift учитываются точно; одинаковые сочетания для двух назначений запрещены. Esc отменяет, «Убрать хоткей» очищает. Клавиши продолжают поступать игре. Работа во всех играх/защищённых окнах не гарантируется; программа не повышает права.

| Эффект | Диапазон | Поведение |
|---|---|---|
| **Усиление** | 100–2000 % (×1…×20), исходно 300 % | Действует на выходе строго при удержании, переход 10 мс. Мягкое насыщение после усиления; при 100 % и без удержания насыщение обходится. Для усиления конца фразы держите кнопку немного дольше. |
| **Перегрузка** (галка) | — | По умолчанию выключена. Жёсткий клиппинг с входным усилением ×12, пик ±0,891. Работает только при удержании усиления выше 100 %, для обоих источников и выходов; без галки — мягкое насыщение. Переключение сглажено за 10 мс. Чтобы в эффект попадали дыхание и клавиатура, снизьте шумоподавление: удалённое NVIDIA не восстанавливается. |
| **Высота** | −12…+12 полутонов, исходно −5 | Pitch без изменения темпа. Для −5 полутонов процессор и согласование блоков добавляют **64,9 мс**; без удержания — полный обход без задержки. При включении/выключении возможен короткий повтор/пропуск, сглаженный за 10 мс. |
| **Замедление / Ускорение** | ×0,50…×0,95 (исходно ×0,70) / ×1,05…×2,00 (исходно ×1,50), шаг ×0,05 | Удерживайте и говорите, затем отпустите: фраза прозвучит с выбранной скоростью и соответствующей высотой. Скорость фиксируется в начале записи. Максимум 10 с в памяти, без файлов. После отпускания захватывается ещё 200 мс окончания слога; при заполнении буфера ждём отпускания. Во время удержания микрофон проходит без заглушения; при воспроизведении звучит обработанная версия; вне фразы задержки нет. |
| **Реверс** | — | Пока удерживаете, обычная речь идёт в чат и записывается. После отпускания — ровно 150 мс тишины, затем только обратная версия с исходным уровнем и скоростью ×1, без дополнительного захвата 200 мс. Конец плавно затухает за 60 мс (для короткой фразы — не дольше половины длины), живой голос возвращается за 10 мс. Лимит 10 с. |

Бережная подрезка реверса: микрофон и Discord автоматически убирают только непрерывные практически беззвучные края от 200 мс, оставляя по 100 мс рядом со звуком; внутренние паузы сохраняются. Анализ по пикам окон 10 мс с порогом `min(0.0001, пик записи × 0.001)`; равенство порогу сохраняет окно. Записи короче 300 мс и с пиком ≤ 0.001 остаются целиком. Шумные края могут не обрезаться. Это пороговая обработка, не распознавание речи.

Правила для фраз: сохраняется сигнал после NVIDIA, RVC и pitch; громкость, boost и Mute действуют на текущее воспроизведение. Отмена, Mute, Stop, потеря клиента, блокировка/сон, переназначение и устаревший опрос клавиш (250 мс) сбрасывают фразу и эффекты — отпустите и снова нажмите хоткей. Новый хоткей во время проигрывания начинает новую запись. Одновременное нажатие нескольких хоткеев фразы отменяет запись/воспроизведение; сначала отпустите все эти клавиши. Оба живых эффекта (усиление и высота) можно удерживать одновременно.

**Повтор последнего** — Ctrl+F8 по умолчанию, сочетание меняется кнопкой рядом. Один общий слот для всех десяти модификаторов, только в памяти, до 20 с обработанного звука (покрывает 10 с записи при ×0,5). Новое удержание заменяет фрагмент; для скорости/реверса сохраняется обработанное воспроизведение. Нажатие после окончания эффекта проигрывает фрагмент поверх живого микрофона; повторное — с начала. Во время записи нового эффекта повтор игнорируется. Микрофон не сохраняется в Discord-фрагмент. Mute, отмена и сбросы останавливают повтор; остановка движка очищает слот. **Усиление не записывается**: его удержание не заменяет фрагмент и не попадает ни в повтор, ни в запись — фрагменты создают только высота, замедление, ускорение и реверс. Discord-громкость применяется при каждом воспроизведении.

**Последние записи** — блок под громкостью Discord на вкладке «Микрофон». Каждый законченный фрагмент сохраняется в `%APPDATA%\Mic Noize\Записи` файлом `Запись ГГГГ-ММ-ДД ЧЧ-ММ-СС.wav` (48 кГц моно, 16 бит); хранятся шесть последних, более старые удаляются при следующей записи. Шесть плиток стоят по три в ряд и помещаются целиком, без прокрутки страницы: на плитке — время записи, клик или Enter проигрывает её как звук саундпада (повторное нажатие останавливает, играющая подсвечена оранжевым). Кнопка **↓** рядом открывает выбор: **В папку саундпада** (если папка ещё не выбрана — сначала предложит её выбрать и сразу подключит) или **В другую папку**. Выбор занимает строку заголовка блока, выбранная плитка обведена; там же показывается результат сохранения или ошибка. Копия не перезаписывает одноимённый файл: к имени добавляется ` (2)`. Дата остаётся в имени файла. Список переживает перезапуск программы. Обе галочки прослушивания стоят слева, под «Слышать весь голос».

### Discord

Захват включает только дерево процессов настольного Discord (Discord, PTB или Canary, одна запущенная версия; браузерный Discord не поддерживается) через официальный [Windows Application Loopback API](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/). Игра, музыка других приложений и наше прослушивание исключены. После назначения Discord-хоткея запустите обработку и дождитесь «Discord · готов»; при перезапуске Discord источник переподключается автоматически, для эффекта нужно новое нажатие.

Усиление и pitch работают во время удержания; скорости записывают фрагмент и проигрывают после отпускания; реверс записывает фрагмент без передачи исходной речи в виртуальный микрофон и через 150 мс проигрывает только обратную версию. Обычный звук Discord в ваших наушниках не выключается. Discord подмешивается к живому микрофону и обходит NVIDIA и RVC; ваш микрофон при этом продолжает проходить шумоподавление и RVC. Источник фразы фиксируется до её окончания.

**Громкость Discord** — общий ползунок 0–200 %, по умолчанию 100 %, сохраняется. Новые 100 % равны прежним 8 % фактического уровня, 200 % — прежним 16 %; старое сохранённое значение `8` мигрирует без изменения слышимой громкости. Ползунок регулирует все пять эффектов Discord после усиления/перегрузки, в дополнение к общей выходной громкости; не меняет уровень микрофонных эффектов. Переход 10 мс, при 0 % Discord замолкает. Принадлежность источнику передаётся вместе с каждым отсчётом через выходную очередь, поэтому громкость не переключается раньше самого звука.

Проверка захвата без NVIDIA и без вывода: `bin\mic_check.exe --discord-capture`.

### Логи

Вкладка «Логи» собирает один текстовый отчёт: версия, видеокарта и её архитектура, драйвер NVIDIA, Windows, состояние движка, выход, прослушивание, текущий статус и последние строки `results/app.log` (40), `sessions.log`, `tag-host.log`, `tag-headphones.log`, `nvafx.log` с временем изменения каждого файла. Повторы подряд схлопываются в `(xN)`, путь профиля заменён на `%USERPROFILE%`. «Копировать всё» пересобирает отчёт и кладёт его в буфер обмена, «Открыть папку» открывает `results`. `app.log` пишет UI: запуск с GPU и каждое новое сообщение строки статуса с UTC-временем (обратный отсчёт перезапуска не дублируется); больше 512 КБ — остаётся новая половина. `nvafx.log` — ошибки NVIDIA SDK (`NvAFX_InitializeLogger`, уровень ERROR, только при ASCII-пути). Строки `tag-host.log` времени не имеют — ориентируйтесь на время изменения файла.

### Прослушивание

**Слышать весь голос** — кнопка или сохраняемый глобальный хоткей включает прослушивание готового виртуального микрофона на устройстве вывода Windows (в голосе уже учтены NVIDIA, RVC, pitch и boost). Работает для TAG, в том числе без Discord. Задержка основного тракта плюс локальное воспроизведение — используйте наушники. Виртуальные выходы CABLE / VoiceMeeter / Broadcast для прослушивания заблокированы от петли. Ошибка прослушивания не останавливает шумодав; при ошибке движка или выходе оно выключается. Если Windows инвалидирует устройство вывода (`AUDCLNT_E_DEVICE_INVALIDATED`: наушники переподключены, сменён выход по умолчанию или формат), прослушивание переоткрывается на текущем выходе через 0,5 с, до 20 попыток подряд.

**Слышать результат эффектов** (`[effects] monitor_effects`) воспроизводит только pitch, скорость, реверс и преобразованный RVC; **Слышать результат эффекта усиления** (`monitor_boost`, по умолчанию выключено) — усиление/перегрузку; **Слышать звуки в наушниках** на вкладке саундпада (`[soundpad] monitor`) — звуки саундпада. Можно включить любую группу или все; совмещённые эффекты слышны при выборе любой группы. Настройки общие для микрофона и Discord; повтор сохраняет категории записанных сэмплов (усиление в них не попадает). Полное прослушивание имеет приоритет.

## Саундпад

Вкладка **Саундпад** проигрывает звуки из выбранной папки поверх голоса в виртуальный микрофон. **Выбрать папку** назначает хранилище (`mp3`, `wav`, `ogg`, `m4a`; вложенные папки не читаются), **Добавить звуки** копирует выбранные файлы в эту папку (одноимённые пропускаются), **Обновить** перечитывает её. Список фильтруется полем поиска и сортируется: **По имени**, **С хоткеем сверху** (назначенные звуки первыми, в порядке клавиш), **Недавно игравшие** (по последнему запуску из списка или хоткеем; время сохраняется), **Новые файлы** (по дате файла). У каждой строки — запуск/стоп кликом или Enter, собственная громкость 0–200 % и хоткей. Шкала и процент громкости строки в покое имеют 15 % непрозрачности, а белый бегунок полностью скрыт; при наведении на строку или сам регулятор всё становится полностью видимым. Список живёт в собственной прокрутке под закреплённой панелью; строятся только строки рядом с видимой областью и отдельно строка с клавиатурным фокусом. Расстояние до выбранного трека не увеличивает число создаваемых строк; пропуски сохраняют высоту списка. При переходе в короткий раздел или сужении поиска звуки остаются видимыми, даже если прежнее положение прокрутки было ниже нового списка. При прокрутке строки перерисовываются целыми полосами, без отдельных проходов для каждой надписи и ползунка. Плавная прокрутка обновляется по кадрам окна с учётом прошедшего времени, без отдельного таймера ожидания на каждый шаг; после остановки анимации подписка на кадры отключается.

Слева — **разделы**: «Все звуки», затем автоматические группы по повторяющемуся началу имени до « - » (`danya - …`, `des - …`; группа появляется от двух файлов, сортировка по размеру), затем свои разделы. **+ Раздел** создаёт раздел (имя вводится сразу, Enter сохраняет; двоеточие, `|` и табуляция вырезаются); выбранный свой раздел можно переименовать и удалить. Звук добавляется в свой раздел перетаскиванием за ≡ в начале строки на имя раздела; × в строке выбранного раздела убирает его оттуда. Разделы хранятся по именам файлов (`[soundpad] sections`), так что перечитывание папки их не теряет. Общая громкость 0–200 % умножается на громкость звука: новые 100 % соответствуют прежним 20 % (физический gain 0,04, около −28 дБ), 200 % — прежним 40 % (gain 0,08). Старые сохранённые 20 % автоматически отображаются как 100 % без изменения слышимого уровня; прежние значения выше 40 % ограничиваются новым максимумом 200 %. «Остановить всё» — хоткей и кнопка.

**Выравнивать громкость** (по умолчанию включено) приводит клипы к общему уровню, не трогая файлы. При загрузке звук измеряется по BS.1770 (LUFS интегральной громкости уже сведённого моно-сигнала, который и звучит; для стерео-файла число примерно на 3 дБ ниже «стерео-LUFS») и умножается на поправку: громче −12 LUFS приглушается до −12, тише −18 поднимается до −18, внутри окна не меняется. Подъём ограничен +12 дБ и пиком −1 dBFS, поэтому тихий клип с резкими пиками может остаться тише окна; приглушение не ограничено. Громкость строки 0–200 % и общая громкость работают поверх выравнивания; громкие клипы могут стать тише прежнего, это компенсируется общей громкостью. Окно задаётся `norm_min`/`norm_max` в `[soundpad]` (−40…−5; перевёрнутая пара даёт значения по умолчанию); `settings.ini` править при закрытом приложении, иначе сохранение перезапишет правку. Записи эффектов выравниваются так же. Переключение галки останавливает играющий клип и перезагружает библиотеку: звуки с хоткеями декодируются заново сразу, остальные при следующем запуске.

Хоткей звука: нажатие играет клип с начала, повторное нажатие того же хоткея останавливает, другой звук заменяет текущий (играет один клип за раз), быстрое двойное нажатие (до 170 мс) перезапускает с начала. Остановка и замена затухают 5 мс. Хоткей назначается прямо на кнопке: клик, нажатие клавиши (можно с Ctrl/Alt/Shift или боковой кнопкой мыши) — и готово; занятое сочетание показывается красным на той же кнопке и ожидание продолжается, повторный клик или Esc отменяет, × рядом убирает назначение. Так же работают все кнопки хоткеев на вкладке «Микрофон». Хоткеи звуков используют ту же схему клавиш и модификаторов, что и эффекты, не могут совпадать с ними и друг с другом, действуют только при работающей обработке и не в Mute; Mute остаётся последним. Звук не проходит через NVIDIA, RVC, pitch, фразы, усиление и громкость Discord: он подмешивается после эффектов в TAG и WASAPI одинаково. Полное прослушивание слышит его как часть голоса; «Слышать результат эффектов/усиления» — нет, для этого есть «Слышать звуки в наушниках»: под галкой видно устройство вывода монитора и уровень, который он реально воспроизводит («тишина» / dBFS), либо причину, почему он не работает.

Клипы декодируются в UI (symphonia) в 48 кГц моно с линейной передискретизацией и живут в памяти движка (~190 КБ на секунду); длиннее 5 минут обрезаются. Звуки с хоткеем загружаются при запуске и назначении, остальные — при первом запуске из списка (кнопка показывает «загрузка…», ошибка декодирования остаётся в строке). Перечитывание папки выгружает все клипы и сохраняет хоткеи и громкости по имени файла.

## RVC (Voice Changer)

Вкладка **Voice Changer** выбирает импортированный слот VCClient из `%APPDATA%\Mic Noize\Components\vendor\vcclient-2.1.4-alpha\dist\main\model_dir\<слот>` (`params.json` и `.pth`/`.onnx`). Dev-сборка использует каталог `vendor` репозитория. Параметры: тон модели −24…+24 полутонов, влияние `.index` 0–100 % (без индексного файла эффекта нет), усиление входа модели 50–300 %, блок 100/150/200/300/500 мс (по умолчанию 200). Сохраняются в `[rvc]` и применяются при следующем запросе. Это отдельный тон модели, не обычный pitch-хоткей; `protect_ratio` эта сборка pipeline не использует.

**Задержка фиксированная: блок + 200 мс** (при 200 мс — ~400 мс), не зависит от лагов модели и не растёт со временем. Первые «блок + 200 мс» после включения, смены настроек или Mute — тишина. Опоздавший звук отбрасывается; если модель не успевает или сервер не отвечает — **тишина, а не обычный голос** (статус «Модель не успевает · пауза»). RVC обрабатывает только микрофон, Discord проходит без модели; Discord-хоткеи не выключают RVC для вашего голоса. Pitch, фразы, повтор и прослушивание работают с уже преобразованным голосом. Mute остаётся последним.

HTTP работает в отдельном потоке. Холодный запуск включает прогрев. Выключение RVC сразу завершает принадлежащее приложению дерево сервера (ожидание ограничено 2 с на этап, ошибка показывается в UI и пишется в `results/rvc-stop-error.log`); при выключенном RVC сервер не запускается, повторное включение требует холодной загрузки. Если сервер упал, UI выключает RVC сам (~250 мс) и обычный голос возвращается; зависший сервер даёт тишину до выключения. Выход из UI также завершает сервер. Абсолютный нулевой расход памяти не заявляется.

**Импорт модели**: выбор одной экспортированной RVC v1/v2 `.pth` и необязательного `.index` (Ctrl + щелчок). Импорт проверяет формат весов на CPU (`weights_only=True`), параметры и размерность индекса, копирует файлы в новый свободный слот и создаёт `params.json`. Исходники и существующие слоты не перезаписываются. Тренировочные checkpoint, legacy pickle/TAR и нестандартные архитектуры не поддерживаются. При выключенном RVC новая модель выбирается; при работающем текущий голос остаётся. Модель можно переименовать в списке; удаление доступно только при выключенном RVC, требует второго подтверждающего нажатия и удаляет весь каталог слота. Старая установка MMVCServerSIO 1.5.3 не используется.

FAISS в установленном VCClient использует `torch/lib/libiomp5md.dll` (исправление конфликта OpenMP: `src/rvc_openmp_fix.py`, оригиналы в `.tmp/rvc-openmp-originals`); после замены VCClient исправление нужно повторить. Сайдкар пересобирается PyInstaller (Python 3.10) при изменении `src/vcclient_server.py` или `src/rvc_import.py`; установленный — `vendor/vcclient-2.1.4-alpha/dist/main/mnr_vcclient_server.exe`.

## Наушники

Вкладка **Наушники** — отдельный выход для стримов: независимые запуск/остановка, физический выход, шумодав NVIDIA v2 (0–200 %; выше 100 % — эксперимент), громкость 0–100 %, тон −12…+12 полутонов и Mute. Настройки — в `[headphones]`; запуск всегда ручной. Выберите физические наушники и нажмите **Включить**, затем в микшере Windows направьте браузер в **Mic Noize Headphones (Thin Audio Gateway)**. После остановки верните выход браузера на физические наушники: виртуальное устройство отключается. Системный выход и настройки Discord не меняются.

Тракт: TAG render → отдельный NVIDIA denoiser на каждый канал → тон → ограниченная стереоочередь → громкость/Mute → WASAPI наушников. При отключённом NVIDIA работает сухой стереотракт. Режим NVIDIA и устройство меняются после остановки. Фильтр предназначен для речи: музыка и атмосфера стрима могут подавляться. Задержка включает обработку и буфер; синхронность видео/аудио не проверена. При выключенном разделе потоки завершены, модели освобождены; хоткеи микрофона не управляют наушниками. Дополнительная CPU/GPU-нагрузка не измерена. Виртуальные выходы запрещены как приёмник (защита от петли). После потери запросов наушников на 2 с их линия в хосте закрывается; микрофон продолжает обслуживаться.

## Настройки

`%APPDATA%\Mic Noize\settings.ini` (UTF-16, совместим с прежними версиями) сохраняется атомарно после короткой паузы изменений и при выходе; неизвестные ключи сохраняются. При первом запуске настройка копируется из старой установки или из корня dev-репозитория. Удержание и текущий Mute не сохраняются; автозапуск хоста хранится в реестре.

- `[audio]`: `input`, `output` (`TAG` или id устройства), `version` (1/2), `intensity`, `alternate_intensity` (0–200), `buffer_ms` (10–80, default 40), `period_ms` (2–20, default 5), `cuda_graphs` (−1 штатно / 0 / 1).
- `[effects]`: `boost`, `overload`, `pitch`, `slow_speed`, `fast_speed`, `discord_volume`, `discord_volume_scale`, `monitor_effects`, `monitor_boost`, `rvc_enabled`, хоткеи `*_key` (код клавиши + модификаторы × 256), `replay_key` (default Ctrl+F8), `monitor_key`, `noise_key`.
- `[rvc]`: `slot`, `pitch`, `index`, `chunk_ms`, `gain`. `[headphones]`: `output`, `denoise`, `intensity`, `volume`, `pitch`. `[ui] tray_hint`.
- `[soundpad]`: `folder`, `volume_display` (общая громкость в интерфейсе, 0–200), `volume` (прежняя шкала для безопасного отката), `monitor` (0/1), `normalize` (0/1, по умолчанию 1), `norm_min`/`norm_max` (окно выравнивания, LUFS, по умолчанию −18/−12, вручную), `stop_key`, `sort` (0 имя, 1 хоткей, 2 недавние, 3 новые), `sections` (`имя:файл|файл` через табуляцию), `sounds` — записи `хоткей:громкость:последний запуск (unix-секунды):имя файла` через табуляцию только для звуков с хоткеем, громкостью ≠ 100 % или запуском.

## Проверки

Без NVIDIA:

```powershell
.\verify.ps1                                  # пересборка проверок, CTest, Rust-тесты, Clippy
.\bin\effects_check.exe                       # DSP: bypass, эффекты, фразы, реверс, повтор, RVC playout
.\bin\bridge_check.exe                        # C ABI, ошибки, контролы, dry bypass RVC
.\bin\mic_check.exe --self-test               # очереди, дрейф, часы TAG
.\bin\MicNoize.exe --ui-benchmark --ui-snapshot "$PWD\results\ui.png"
```

QA-флаги UI: `--ui-settings`, `--ui-logs`, `--ui-rvc`, `--ui-headphones`, `--ui-small`, `--ui-scale 2` с `--ui-snapshot`; `--ui-benchmark` без снимка открывает, закрывает в трей и повторно открывает окно. Запускайте при закрытом обычном экземпляре. `--start-tray` запускает без окна.

С железом (перед GPU-тестами проверьте свободную VRAM, оставляйте 2–4 ГБ; индексы устройств меняются — сверяйте через `--list`):

```powershell
.\bin\mic_check.exe --list
.\bin\mic_check.exe --smoke INPUT_INDEX TAG 60 2 40          # реальный микрофон → NVIDIA → TAG, 60 с
.\bin\mic_check.exe --smoke-phrases INPUT_INDEX TAG 14 2 40  # фразы обеих скоростей и сброс через Mute
.\bin\mic_check.exe --monitor-check INPUT_INDEX TAG          # прослушивание, Mute, остановка
.\bin\mic_check.exe --persistent-tag INPUT_INDEX             # тот же endpoint через два жизненных цикла движка
.\bin\mic_check.exe --lifecycle-tag INPUT_INDEX              # отсутствующий вход, 12 подключений, 48k/44.1k
.\bin\mic_check.exe --tag-reconnect INPUT_INDEX              # стойла 120/400 мс переживаются без остановки
.\bin\mic_check.exe --discord-capture                        # захват Discord без вывода
.\bin\mic_check.exe --headphones-check OUTPUT_INDEX 0|1      # стерео-тракт наушников, сухой / NVIDIA
.\bin\mic_check.exe --rvc-check                              # RvcClient против запущенного сайдкара
python .\src\rvc_check.py                                    # HTTP-контракт сайдкара
python .\src\rvc_import_check.py                             # импорт модели (CPU, из .tmp\pyi310-venv)
```

`--smoke` при выборе физического выхода воспроизводит обработанный микрофон на нём. Ненулевой код завершения означает ошибку, отсутствие обработки или пропуски. Замеры задержки (`--record-pair`, `--record-routes`, `--probe-cable`, `analyze-latency.py`) и A/B CUDA Graphs (`--bench-afx`, `analyze-afx.py`) описаны в CHANGELOG; они требуют NumPy в локальной `.venv` и частично VB-CABLE, который удалён. Только `--record-pair`/`--record-routes` сохраняют локальные аудиопакеты; обычная работа и smoke-тесты не записывают звук.

Диагностика: `run_max_ms` — `NvAFX_Run`, `reset_max_ms` — `NvAFX_Reset`; `gaps`/`underruns` — нехватка готового звука, `drops` — сброс переполненной очереди, `TAG_gaps` — счётчики драйвера, `late_ticks` — опоздания хоста, `reconnects` — переподключения к TAG-хосту, `runs_over_5ms`/`runs_over_10ms` — сколько 10-мс блоков `NvAFX_Run` обрабатывал дольше 5/10 мс (отличает единичный пик от постоянной перегрузки), `run_max_at_s` — секунда сеанса, на которой был максимум, `failed_at` — UTC-время сбоя (строка пишется при следующей остановке, иногда намного позже). После корректной остановки движка итог сеанса дописывается в `results/sessions.log` (без записи голоса); принудительно убитый процесс и старт, упавший до запуска потоков, строки не оставляют. `mic_check --bench-afx <pcm> <сек> <graphs> <csv> [churn]` меряет каждый блок NVIDIA офлайн; `churn` добавляет смену силы и `reset` как в реальном сеансе. `run-tag.ps1` запускает консольный прототип `mic_tag.exe` (не одновременно с UI); `run-sample.ps1 -Version 1|2` — официальный файловый пример NVIDIA после `build.ps1 -Samples`.

## Ограничения и что не проверено человеком

- Субъективное звучание pitch/насыщения/RVC на вашей речи в Discord, реальные игровые хоткеи, физическое извлечение USB, блокировка/сон и перезапуск Explorer — код есть, физическая проверка не проводилась. FPS не измерялся. Настройки Discord автоматически не менялись; его AGC может уменьшать заметность boost.
- Denoiser v1 не считается стабильным режимом под нагрузкой; причина редких длинных вызовов NVIDIA (до 224 мс) не установлена, запас 40 мс их не покрывает.
- Стойло аудиопотока дольше 2 с останавливает обработку (watchdog микрофона); восстановление после сна/USB — вручную через «Обновить устройства».
- Носители: TAG demo, GPL Rubber Band и NVIDIA-модели делают сборку непригодной к распространению без отдельного решения по лицензиям.
